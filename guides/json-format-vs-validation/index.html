JSON을 예쁘게 정리하는 것과 올바르게 만드는 것은 다릅니다

JSON 포맷과 구문 검증의 차이를 작은 예제로 설명하는 실습 가이드.

실제 서비스 인터페이스 화면이며 입력 텍스트는 합성 예제입니다.

들여쓰기는 읽기 쉽게 할 뿐입니다

줄바꿈과 들여쓰기를 맞추면 구조를 읽기 쉬워지지만, 누락된 쉼표나 따옴표를 자동으로 올바르게 만들지는 않습니다. 보기 좋은 출력과 유효한 데이터는 별개의 확인 항목입니다.

작은 입력으로 오류 위치를 찾습니다

중괄호, 대괄호, 키와 문자열의 따옴표를 짧은 예제로 하나씩 확인합니다. 오류 메시지가 나온 위치 주변을 보고 한 번에 여러 규칙을 바꾸지 않으면 원인을 추적하기 쉽습니다.

다음 시스템에 넣기 전에 다시 검사합니다

정리한 JSON을 복사한 뒤에는 실제로 사용하는 API, 설정 파일, 도구가 받아들이는지 확인합니다. 포맷터의 결과만 보고 데이터 의미가 바뀌지 않았다고 단정하지 않습니다.

최종 확인

결과 파일을 편집기 미리보기만으로 승인하지 말고, 실제로 쓰일 크기와 위치에서 다시 확인합니다. 도구 화면과 옵션은 바뀔 수 있으므로 현재 사용 방법은 연결된 공개 도구 페이지에서 확인하세요.
